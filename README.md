# MegaFighter

Браузерный файтинг в духе Mortal Kombat: Three.js-графика, один игрок против ИИ,
играется и мышью-клавиатурой на десктопе, и пальцами на телефоне. Ассетов нет вообще —
бойцы, арена, эффекты и звук генерируются кодом.

## Какой фреймворк и почему именно он

**Vite + TypeScript + Three.js напрямую, без игрового движка.** Это ответ на исходный вопрос,
и вот рассуждение за ним:

| Вариант | Вердикт |
| --- | --- |
| **Vite + TS + Three.js** | ✅ Выбран. Three.js уже назван в задаче; Vite даёт мгновенный HMR и сборку в статику, которую можно положить на любой хостинг. Полный контроль над игровым циклом — для файтинга это не роскошь, а требование. |
| Babylon.js | Мощнее «из коробки» (физика, редактор), но тяжелее и навязывает свою архитектуру. Физика файтинга всё равно пишется вручную. |
| PlayCanvas / Unity WebGL | Редактор и готовый пайплайн, но сборка Unity WebGL — это десятки мегабайт и болезненный старт на мобильном. Для 2.5D-файтинга это оплата за то, чем не пользуешься. |
| Phaser / PixiJS | Отличны для 2D, но тогда не будет Three.js-графики. |
| React / Vue поверх игры | ❌ В игровом цикле — вред: лишние ре-рендеры в кадре. Меню и HUD здесь — обычный DOM, он обновляется раз в кадр точечными записями в стили. |

Ключевое решение: **игровая логика не знает про Three.js**. Симуляция (`src/game`, `src/characters`)
— чистый TypeScript без импортов рендера. Благодаря этому её можно гонять в Node без браузера
(см. `npm run sim`), а позже подменить рендер или добавить сетевой код, не трогая боевую систему.

## С чего начать

```bash
npm install
npm run dev        # http://localhost:5173, с телефона — по адресу из строки Network
npm run build      # проверка типов + сборка в dist/
npm run preview    # посмотреть собранную версию
```

`dist/` — статика, её достаточно выложить на любой хостинг (GitHub Pages, Netlify, Cloudflare Pages).
`base: './'` в `vite.config.ts` уже настроен на раздачу из подпапки.

Порядок, в котором стоит читать код, если хочется что-то поменять:

1. `src/game/constants.ts` — гравитация, размеры арены, длительность раунда.
2. `src/characters/moveFactory.ts` — фрейм-дата нормалей и шаблоны спешлов.
3. `src/characters/roster.ts` — восемь бойцов; новый персонаж = один объект `Blueprint`.
4. `src/game/fighter.ts` — конечный автомат бойца.
5. `src/render/fighterModel.ts` — как из чисел собирается трёхмерная модель.

## Публикация на GitHub Pages

Деплой настроен: `.github/workflows/deploy.yml` собирает проект и публикует `dist/`
по адресу **https://mevdad.github.io/MegaFighter/**. Каждый push в ветку по умолчанию
переопубликует игру; вручную — **Actions → Deploy to GitHub Pages → Run workflow**.

### Источник Pages должен быть «GitHub Actions»

Сейчас так и настроено. Раздел оставлен на случай переноса проекта в другой репозиторий —
там этот шаг придётся повторить, и без него сайт молча не работает.

Если в **Settings → Pages → Build and deployment** источником стоит ветка, GitHub на каждый
push запускает свою штатную сборку «pages build and deployment», которая выкладывает
**корень репозитория как есть**. А в корне лежит `index.html` со ссылкой на `/src/main.ts` —
сырой TypeScript по абсолютному пути, то есть для project pages ещё и мимо подпапки.
Браузер получает 404 и показывает пустую страницу. Хуже того, эта публикация завершается
позже нашей и затирает собранный `dist/`.

Параметр `enablement: true` у `actions/configure-pages` в workflow это **не** чинит: он
включает Pages там, где их нет вовсе, но не меняет источник у уже настроенного сайта.
Проверено на этом репозитории — после прогона с ним штатная сборка из ветки запустилась снова.
Так что переключение делается руками, один раз:

**Settings → Pages → Build and deployment → Source: `GitHub Actions`**

После переключения «pages build and deployment» перестаёт появляться в Actions.

Проверить, что именно опубликовано, можно по исходному коду страницы:
`src="./assets/index-*.js"` — выложена сборка, всё в порядке;
`src="/src/main.ts"` — выложены исходники, источник ещё не переключён.

### Остальное про workflow

- Он собирает **только ветку по умолчанию** — условие написано через
  `github.event.repository.default_branch`, поэтому переименование ветки (например, в `main`)
  ничего не сломает и править YAML не придётся.
- `npm run build` — это `tsc --noEmit` + `vite build`, так что ошибка типов остановит деплой
  до публикации, а не после.
- `concurrency: pages` с `cancel-in-progress: false` не даёт двум деплоям наложиться
  и при этом не обрывает уже начавшийся.

**Почему не нужно менять `base` в `vite.config.ts`.** Project Pages отдают сайт из подпапки
(`/MegaFighter/`), и при `base: '/'` все ассеты вели бы в корень домена и получили бы 404.
Здесь стоит `base: './'` — относительные пути, которые одинаково работают и на
`localhost:4173`, и в подпапке, и на своём домене. Проверено прогоном собранной игры,
разложенной в подпапку: ни одного 404, бой стартует.

Запасной путь без Actions — собрать локально и выложить содержимое `dist/` в ветку `gh-pages`,
выбрав её источником в Settings → Pages. Тогда рядом с `index.html` положите пустой файл
`.nojekyll`, иначе Jekyll может съесть часть файлов сборки.

## Управление

| Действие | Клавиатура | Телефон |
| --- | --- | --- |
| Движение | `A` / `D` или `←` `→` | стик слева |
| Присед | `S` / `↓` | стик вниз |
| Прыжок | `W` / `↑` | стик вверх |
| Блок | `Пробел` или шаг назад | кнопка **БЛОК** |
| Слабый / сильный удар рукой | `J` / `K` | **СЛ.РУКА** / **СИЛ.РУКА** |
| Лоу-кик / хай-кик | `L` / `;` | **СЛ.НОГА** / **СИЛ.НОГА** |
| Бросок | слабая рука + слабая нога | кнопка **БРОСОК** |
| Спешл | мотион + удар | кнопка **СПЕШЛ** сама набирает ↓ ↘ → + сильная рука |
| Пауза | `Esc` | кнопка **ПАУЗА** |

Поддерживается геймпад (стандартный маппинг), клавиатура и тач работают одновременно.

Базовые приёмы: рывок — двойное нажатие вперёд/назад (назад даёт кадры неуязвимости);
подсечка — `↓` + хай-кик (сбивает с ног, блокируется только в присяде); апперкот —
`↓` + сильная рука (медленный, но подбрасывает и сносит с ног); супер — `↓↘→ ↓↘→` +
сильная рука при полной шкале.

**Присед — это ещё и уклон.** Удары рукой и хай-кик проходят над головой присевшего
и не попадают вовсе. Поэтому сидящего в приседе вскрывают лоу-киком, подсечкой,
апперкотом или броском — ровно как в Mortal Kombat.

**Комбо строятся так:** попал слабым ударом — жми следующий, более сильный
(слабая рука → нога → сильная рука); после попадания нормалью можно сразу ввести мотион
спешла, и нормаль отменится в него. Приём разрешено нажимать заранее — буфер ввода
выполнит его, как только боец освободится.

## Бойцы

Восемь персонажей с разными архетипами: **КАЙРА** (рашдаун), **ОБСИДИАН** (грэпплер),
**ВОЛЬТА** (зонер), **НОКС** (ассасин с телепортом), **ЖАР** (сбалансированный),
**ТЕРРАКС** (брузер), **СИРЕНА** (воздушный бой), **ХРОМ** (универсал).

Каждый описан данными: палитра, телосложение, статы, три спешла и супер. Модель, силуэт
(рога, визор, плащ, наплечники, пучок, нимб), цвет ауры и эффектов выводятся из этих данных,
поэтому добавить бойца — значит дописать один объект, а не рисовать спрайты.

Кнопка **СГЕНЕРИРОВАТЬ БОЙЦА** в главном меню создаёт нового персонажа процедурно
(`src/characters/generator.ts`): архетип, имя, палитра вокруг случайного тона, телосложение,
статы и набор спешлов. Генератор детерминирован — один сид всегда даёт одного и того же бойца.

## Модели бойцов

**КАЙРА**, **ХРОМ** и **ТЕРРАКС** — настоящие модели людей со скелетом и скиннингом;
остальные пять собираются из примитивов прямо в рантайме.

Анимации из файлов **не проигрываются**. Вся боевая анимация задана позами и фрейм-датой,
иначе тайминги ударов перестали бы совпадать с хитбоксами и фрейм-дата потеряла бы смысл.
Вместо этого кости модели доворачиваются так, чтобы смотреть туда же, куда смотрят кости
нашего процедурного скелета (`src/render/realisticModel.ts`). Ретаргет «по направлению»
не требует совпадения систем координат и работает на любой модели с человеческим скелетом —
добавить очередного персонажа значит положить GLB в `public/models` и дописать одну строку
в `roster.ts`.

Модели Кайры и Хрома — из примеров three.js (`examples/models/gltf/Michelle.glb` и
`Soldier.glb`), исходно персонажи Adobe Mixamo. Терракс — модель с собственным Mixamo-ригом
и набором мокап-анимаций (`public/models/warrior.glb`). Для своего проекта проверьте условия
лицензии источника — особенно если планируете коммерческий релиз. Заменить любую модель на
свою легко: формат GLB, скелет — любой человеческий, имена костей сопоставляются в `BONE_MAP`.

Загрузка идёт в фоне: меню уже крутится, а модели подтягиваются и подменяют примитивы.
Если файлы не приехали, все бойцы останутся процедурными, и играть это не мешает.
Модель Терракса тяжелее остальных (≈11 МБ, три PBR-текстуры) — это заметно на первой загрузке.

### Хай-кик, запечённый из настоящего мокапа

Терракс пришёл не только с моделью, но и с шестью мокап-анимациями. Проигрывать их напрямую
нельзя (см. выше — сломает синхронизацию с хитбоксами), поэтому вместо этого `npm run bake:mocap`
прогоняет анимацию через прямую кинематику, получает мировые направления костей мокап-скелета
на выбранном кадре и «переливает» их в наш процедурный риг тем же способом, каким
`realisticModel.ts` на лету доворачивает модель под наши позы — только офлайн и в обратную
сторону. Результат — обычный `Pose`-объект, который ничем не отличается от нарисованного
вручную и работает для всех бойцов, не только для Терракса.

Так запечён хай-кик (`ROUNDHOUSE` в `src/game/attackClips.ts`, из анимации `front_kick_02`).
Времена ключевых кадров — не автопоиск, а результат покадрового визуального прогона
через отдельный debug-харнесс с `THREE.AnimationMixer`: первая версия автопоиска (искала
пик по расстоянию кисти/стопы до плеча/бедра) на анимации `box_02` приняла защитную
стойку-покачивание за джеб, а на `front_kick_01` промахнулась мимо настоящего удара
на полсекунды. Тем же визуальным прогоном выяснилось, что `box_02`, `hit_to_side` и
`hit_to_body_01` в этом конкретном ассете — вариации одной защитной стойки без реального
удара или отшатывания. Поэтому джеб, кросс и реакции на попадание остались рисованными
вручную: лучше рабочая ручная поза, чем защитная стойка, выданная за удар.

```bash
npm run bake:mocap -- public/models/warrior.glb   # перезаписывает src/game/mocapPoses.ts
npm run check:mocap                                # проверяет, что интерполяция клипа гладкая
```

## Как устроен бой

- **Фиксированный шаг 60 Гц.** Логика идёт ровно 60 раз в секунду независимо от частоты экрана,
  рендер — свободно. Иначе фрейм-дата перестаёт что-либо значить, а на 120-герцовом телефоне
  игра поехала бы вдвое быстрее.
- **Фрейм-дата.** У каждого приёма есть стартап, активные кадры и восстановление; хитбокс живёт
  только в активной фазе, и одно попадание на приём.
- **Блок по высоте.** Низкие атаки блокируются только в присяде, оверхеды — только стоя,
  в воздухе блока нет. Блок держится шагом назад или отдельной кнопкой.
- **Хитстоп.** При попадании бой замирает на 4–17 кадров — главный источник ощущения удара.
- **Комбо и масштабирование урона.** Каждый следующий удар в связке слабее (до 28% от базового),
  иначе любой подброс превращался бы в мгновенный нокаут.
- **Буфер ввода.** Приём, нажатый за 9 кадров до того, как боец освободится, всё равно
  выполнится. Без буфера в приём нужно попадать ровно в кадр, и управление ощущается вязким.
- **Цепочки нормалей.** После попадания можно продолжить более сильным ударом — ранг строго
  растёт, поэтому джеб не может зациклиться сам в себя.
- **Контрудары.** Попадание по противнику, который уже начал замах, даёт +30% урона,
  больше стана и отдельный эффект: это награда за чтение соперника.
- **Броски.** Слабая рука и слабая нога вплотную — захват проходит сквозь блок. Ответ —
  встречный бросок в окно 10 кадров, тогда захват срывается без урона.
- **Потолок жонглирования.** Подброшенного можно добить максимум четырьмя ударами,
  дальше подброс не работает и связка обязана закончиться.
- **Неуязвимость.** Несколько кадров на подъёме с земли и в начале рывка назад — иначе
  упавшего можно было бы держать внизу бесконечно.
- **Уклон приседом.** Высокие удары проходят над присевшим противником — присед даёт
  не только блок снизу, но и полноценный уход от удара.
- **Добивание.** После последнего нокаута проигравший остаётся стоять оглушённым, и у
  победителя есть окно на `↓` + сильная рука. Успел — срабатывает именной финиш со столбом
  света; не успел — матч просто заканчивается победой. Добивание стилизованное, без расчленёнки.
- **Шкала супера** копится от нанесённого и полученного урона, тратится на супер за 100%.
- **Матч** — до двух побед, 99 секунд на раунд; по истечении времени побеждает тот,
  у кого больше процент здоровья.

Анимация процедурная: скелет из вложенных `THREE.Group`, позы — наборы поворотов костей
(`src/game/poses.ts`), удары — клипы, которые проигрываются ровно за длительность приёма
(`src/game/attackClips.ts`). Ни одного внешнего файла модели или текстуры.

## Телефон

- Экранный стик и шесть кнопок появляются только на тач-устройствах.
- Кнопка **СПЕШЛ** раскладывает мотион по кадрам — на телефоне точный ввод ↓↘→ недостижим,
  и без неё спешлы были бы неиграбельны.
- Размеры контролов считаются от меньшей стороны экрана (`vmin`), поэтому низкий ландшафт
  на телефоне не раздувает кнопки на пол-арены.
- В портретной ориентации показывается подсказка повернуть экран: в вертикальном кадре
  два бойца физически не помещаются на комфортном расстоянии.
- Качество определяется на старте: на слабых устройствах отключаются тени и режется pixelRatio.
- Весь звук синтезируется в WebAudio — ноль сетевых запросов за ассетами.

## Инструменты разработки

```bash
npm run sim -- 5 normal   # круговой турнир ИИ против ИИ, 5 кругов: баланс ростера
npm run check:finisher    # окно добивания: срабатывает по вводу и не подвешивает матч
npm run check:mocap       # мокап-клипы: интерполяция между ключевыми кадрами без скачков
npm run bake:mocap -- <glb>  # перезапекает позы из мокап-анимаций в src/game/mocapPoses.ts
npm run smoke             # браузерный прогон меню → бой на десктопе и мобильном ландшафте
npm run typecheck
```

`npm run sim` гоняет бой без браузера и печатает по каждому бойцу процент побед, нанесённый
и полученный урон. Именно он поймал инвертированное определение проигравшего при нокауте
и двукратный разброс эффективного запаса здоровья, из-за которого один боец выигрывал 96% матчей,
а другой — 4%. Текущий разброс на сложности «Боец» — 46–57% при 224 матчах.

## Что дальше

- Аркадная лестница с боссом и концовками для каждого бойца.
- Локальный бой вдвоём за одной клавиатурой (симуляция уже принимает два ввода).
- Онлайн с откатом (rollback): симуляция детерминирована и отделена от рендера — фундамент готов.
- Стилизованные добивания (у каждого бойца имя уже есть в `finisher`).
- Настоящие модели для остальных пяти бойцов — механика ретаргета уже готова.
- Запечь мокап-джеб/кросс из более качественного источника — текущий ассет для них не подошёл
  (см. «Хай-кик, запечённый из настоящего мокапа»), но пайплайн `bake:mocap` готов принять любой.
- Индивидуальные анимации добивания вместо общего столба света.
- EX-версии спешлов за четверть шкалы.
- Тренировочный режим с отображением хитбоксов и фрейм-даты.
