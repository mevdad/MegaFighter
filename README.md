# MegaFighter

Браузерный файтинг в духе Mortal Kombat: Three.js-графика, один игрок против ИИ,
играется и мышью-клавиатурой на десктопе, и пальцами на телефоне. Ассетов нет вообще —
бойцы, арена, эффекты и звук генерируются кодом.

## Какой фреймворк и почему именно он

**Vite + TypeScript + Three.js напрямую, без игрового движка.** Это ответ на исходный вопрос,
и вот рассуждение за ним:

| Вариант | Вердикт |
| --- | --- |
| **Vite + TS + Three.js** | ✅ Выбран. Three.js уже назван в задаче; Vite даёт мгновенный HMR и сборку в статику, которую можно положить на любой хостинг. Полный контроль над игровым циклом — для файтинга это не роскошь, а требование. |
| Babylon.js | Мощнее «из коробки» (физика, редактор), но тяжелее и навязывает свою архитектуру. Физика файтинга всё равно пишется вручную. |
| PlayCanvas / Unity WebGL | Редактор и готовый пайплайн, но сборка Unity WebGL — это десятки мегабайт и болезненный старт на мобильном. Для 2.5D-файтинга это оплата за то, чем не пользуешься. |
| Phaser / PixiJS | Отличны для 2D, но тогда не будет Three.js-графики. |
| React / Vue поверх игры | ❌ В игровом цикле — вред: лишние ре-рендеры в кадре. Меню и HUD здесь — обычный DOM, он обновляется раз в кадр точечными записями в стили. |

Ключевое решение: **игровая логика не знает про Three.js**. Симуляция (`src/game`, `src/characters`)
— чистый TypeScript без импортов рендера. Благодаря этому её можно гонять в Node без браузера
(см. `npm run sim`), а позже подменить рендер или добавить сетевой код, не трогая боевую систему.

## С чего начать

```bash
npm install
npm run dev        # http://localhost:5173, с телефона — по адресу из строки Network
npm run build      # проверка типов + сборка в dist/
npm run preview    # посмотреть собранную версию
```

`dist/` — статика, её достаточно выложить на любой хостинг (GitHub Pages, Netlify, Cloudflare Pages).
`base: './'` в `vite.config.ts` уже настроен на раздачу из подпапки.

Порядок, в котором стоит читать код, если хочется что-то поменять:

1. `src/game/constants.ts` — гравитация, размеры арены, длительность раунда.
2. `src/characters/moveFactory.ts` — фрейм-дата нормалей и шаблоны спешлов.
3. `src/characters/roster.ts` — восемь бойцов; новый персонаж = один объект `Blueprint`.
4. `src/game/fighter.ts` — конечный автомат бойца.
5. `src/render/fighterModel.ts` — как из чисел собирается трёхмерная модель.

## Публикация на GitHub Pages

Деплой настроен: `.github/workflows/deploy.yml` собирает проект и публикует `dist/`
по адресу **https://mevdad.github.io/MegaFighter/**. Каждый push в ветку по умолчанию
переопубликует игру; вручную — **Actions → Deploy to GitHub Pages → Run workflow**.

### Источник Pages должен быть «GitHub Actions»

Это не косметическая настройка, а условие работоспособности. Если в
**Settings → Pages → Build and deployment** источником осталась ветка, GitHub на каждый push
запускает свою штатную сборку «pages build and deployment», которая выкладывает
**корень репозитория как есть**. А в корне лежит `index.html` со ссылкой на `/src/main.ts` —
сырой TypeScript, который браузер исполнить не может. Эта публикация завершается позже нашей
и затирает собранный `dist/`, так что по адресу открывается пустая страница.

В workflow стоит `enablement: true` у `actions/configure-pages`, но он включает Pages только
там, где они ещё не включены вовсе, и **не меняет источник** у уже настроенного сайта.
Проверено на этом репозитории: после прогона с `enablement: true` штатная сборка из ветки
запустилась снова. Так что переключение — это одно действие руками, его не заменить кодом:

**Settings → Pages → Build and deployment → Source: `GitHub Actions`**

После переключения «pages build and deployment» перестанет появляться в Actions.
Чтобы не ждать следующего пуша, запустите публикацию сразу:
**Actions → Deploy to GitHub Pages → Run workflow**.

Проверить, что сейчас опубликовано, можно так: открыть `https://mevdad.github.io/MegaFighter/`
и посмотреть исходный код страницы. Если там `src="./assets/index-*.js"` — выложена сборка,
всё в порядке. Если `src="/src/main.ts"` — выложены исходники, источник Pages ещё не переключён.

### Остальное про workflow

- Он собирает **только ветку по умолчанию** — условие написано через
  `github.event.repository.default_branch`, поэтому переименование ветки (например, в `main`)
  ничего не сломает и править YAML не придётся.
- `npm run build` — это `tsc --noEmit` + `vite build`, так что ошибка типов остановит деплой
  до публикации, а не после.
- `concurrency: pages` с `cancel-in-progress: false` не даёт двум деплоям наложиться
  и при этом не обрывает уже начавшийся.

**Почему не нужно менять `base` в `vite.config.ts`.** Project Pages отдают сайт из подпапки
(`/MegaFighter/`), и при `base: '/'` все ассеты вели бы в корень домена и получили бы 404.
Здесь стоит `base: './'` — относительные пути, которые одинаково работают и на
`localhost:4173`, и в подпапке, и на своём домене. Проверено прогоном собранной игры,
разложенной в подпапку: ни одного 404, бой стартует.

Запасной путь без Actions — собрать локально и выложить содержимое `dist/` в ветку `gh-pages`,
выбрав её источником в Settings → Pages. Тогда рядом с `index.html` положите пустой файл
`.nojekyll`, иначе Jekyll может съесть часть файлов сборки.

## Управление

| Действие | Клавиатура | Телефон |
| --- | --- | --- |
| Движение | `A` / `D` или `←` `→` | стик слева |
| Присед | `S` / `↓` | стик вниз |
| Прыжок | `W` / `↑` | стик вверх |
| Блок | `Пробел` или шаг назад | кнопка **БЛОК** |
| Слабая рука / сильная рука | `J` / `K` | **СЛ.РУКА** / **СИЛ.РУКА** |
| Слабая нога / сильная нога | `L` / `;` | **СЛ.НОГА** / **СИЛ.НОГА** |
| Спешл | мотион + удар | кнопка **СПЕШЛ** сама набирает ↓ ↘ → + сильная рука |
| Пауза | `Esc` | кнопка **ПАУЗА** |

Поддерживается геймпад (стандартный маппинг), клавиатура и тач работают одновременно.

Базовые приёмы: рывок — двойное нажатие вперёд/назад; подсечка — `↓` + сильная нога
(блокируется только в присяде); апперкот — `↓` + сильная рука (подбрасывает для комбо);
супер — `↓↘→ ↓↘→` + сильная рука при полной шкале. Попав нормалью, можно сразу ввести
мотион спешла — нормаль отменится в него.

## Бойцы

Восемь персонажей с разными архетипами: **КАЙРА** (рашдаун), **ОБСИДИАН** (грэпплер),
**ВОЛЬТА** (зонер), **НОКС** (ассасин с телепортом), **ЖАР** (сбалансированный),
**ТЕРРАКС** (брузер), **СИРЕНА** (воздушный бой), **ХРОМ** (универсал).

Каждый описан данными: палитра, телосложение, статы, три спешла и супер. Модель, силуэт
(рога, визор, плащ, наплечники, пучок, нимб), цвет ауры и эффектов выводятся из этих данных,
поэтому добавить бойца — значит дописать один объект, а не рисовать спрайты.

Кнопка **СГЕНЕРИРОВАТЬ БОЙЦА** в главном меню создаёт нового персонажа процедурно
(`src/characters/generator.ts`): архетип, имя, палитра вокруг случайного тона, телосложение,
статы и набор спешлов. Генератор детерминирован — один сид всегда даёт одного и того же бойца.

## Как устроен бой

- **Фиксированный шаг 60 Гц.** Логика идёт ровно 60 раз в секунду независимо от частоты экрана,
  рендер — свободно. Иначе фрейм-дата перестаёт что-либо значить, а на 120-герцовом телефоне
  игра поехала бы вдвое быстрее.
- **Фрейм-дата.** У каждого приёма есть стартап, активные кадры и восстановление; хитбокс живёт
  только в активной фазе, и одно попадание на приём.
- **Блок по высоте.** Низкие атаки блокируются только в присяде, оверхеды — только стоя,
  в воздухе блока нет. Блок держится шагом назад или отдельной кнопкой.
- **Хитстоп.** При попадании бой замирает на 4–17 кадров — главный источник ощущения удара.
- **Комбо и масштабирование урона.** Каждый следующий удар в связке слабее (до 28% от базового),
  иначе любой подброс превращался бы в мгновенный нокаут.
- **Шкала супера** копится от нанесённого и полученного урона, тратится на супер за 100%.
- **Матч** — до двух побед, 99 секунд на раунд; по истечении времени побеждает тот,
  у кого больше процент здоровья.

Анимация процедурная: скелет из вложенных `THREE.Group`, позы — наборы поворотов костей
(`src/game/poses.ts`), удары — клипы, которые проигрываются ровно за длительность приёма
(`src/game/attackClips.ts`). Ни одного внешнего файла модели или текстуры.

## Телефон

- Экранный стик и шесть кнопок появляются только на тач-устройствах.
- Кнопка **СПЕШЛ** раскладывает мотион по кадрам — на телефоне точный ввод ↓↘→ недостижим,
  и без неё спешлы были бы неиграбельны.
- Размеры контролов считаются от меньшей стороны экрана (`vmin`), поэтому низкий ландшафт
  на телефоне не раздувает кнопки на пол-арены.
- В портретной ориентации показывается подсказка повернуть экран: в вертикальном кадре
  два бойца физически не помещаются на комфортном расстоянии.
- Качество определяется на старте: на слабых устройствах отключаются тени и режется pixelRatio.
- Весь звук синтезируется в WebAudio — ноль сетевых запросов за ассетами.

## Инструменты разработки

```bash
npm run sim -- 5 normal   # круговой турнир ИИ против ИИ, 5 кругов: баланс ростера
npm run smoke             # браузерный прогон меню → бой на десктопе и мобильном ландшафте
npm run typecheck
```

`npm run sim` гоняет бой без браузера и печатает по каждому бойцу процент побед, нанесённый
и полученный урон. Именно он поймал инвертированное определение проигравшего при нокауте
и двукратный разброс эффективного запаса здоровья, из-за которого один боец выигрывал 96% матчей,
а другой — 4%. Текущий разброс на сложности «Боец» — 40–57% при 280 матчах.
